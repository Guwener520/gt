# 选题：面向代码智能体的开发任务上下文追踪与代码变更溯源系统

> 本文件是选题原文与结构化拆解，供写作与实现时对齐；与 `AGENTS.md` 第 1–3 节保持同步。

## 一、选题原文

近年来，代码智能体逐渐应用于日常软件开发。开发者可以通过自然语言任务请求，让代码智能体完成代码分析、文件修改、工具调用、测试执行和问题排查等工作。现有智能编程工具虽然能够展示历史对话、代码差异、工具调用记录和测试结果，但这些信息通常分散在不同界面或不同类型的记录中，缺少围绕具体开发任务的组织与关联。开发者在处理多轮修改、多个并行任务或中断后重新开始的任务时，往往难以快速了解当前进展、代码修改的原因及其验证依据，需要依靠人工查找和回忆来恢复开发过程。

本课题面向单个开发者使用代码智能体完成开发任务的场景，研究开发任务、对话内容、代码变更、工具执行和测试结果之间的关联与组织方法，设计并实现支持任务上下文追踪和代码变更溯源的原型系统。系统能够帮助开发者围绕任务、文件或代码片段查看相关对话、修改记录、执行过程和测试结果，并在任务中断或重新开始时恢复必要的上下文。课题还将探索利用大语言模型辅助生成任务摘要、识别信息关联和整理开发进展，并通过典型编程任务评估系统在代码理解、修改原因分析、问题定位和任务衔接方面的作用。

## 二、关键词

代码智能体（code agent）；开发任务（development task）；上下文追踪（context tracking）；
代码变更溯源（code change provenance）；开发过程数据（developer process data）；大语言模型（LLM）

## 三、研究问题（RQ）

- **RQ1 表示**：如何用一个统一的信息模型表示「任务—对话—变更—执行—测试」五类异构记录及其关联？
- **RQ2 关联**：在没有可靠显式标识的情况下，如何把对话片段、工具调用与具体代码变更、测试结果正确关联（并处理行号漂移、重写、回退）？
- **RQ3 溯源**：如何把关联结果组织成开发者可读、可追问的证据链，支撑「为什么改」「依据是什么」「还有效吗」？
- **RQ4 续接**：任务中断后，如何自动重建足够的最小上下文（进展、未完成项、待验证修改）以缩短恢复时间？
- **RQ5 评估**：该系统在代码理解、修改原因分析、问题定位、任务衔接四个维度上，相对「git + 聊天记录」基线是否有可测量的改进？

## 五、创新点（写作时按「相对现有工具」表述，避免夸大）

1. **以任务为中心的组织模型**：把分散的对话/diff/工具调用/测试统一挂到 Task 下，形成可查询的任务上下文图。
2. **细粒度变更溯源**：溯源粒度到 hunk/代码片段，并显式记录「验证依据」（哪次测试、什么结果）与「后续演化」（回退/重写）。
3. **面向中断恢复的上下文重建**：把「任务续接」作为一等功能，而非聊天历史的简单回放。
4. **LLM 辅助关联与摘要的可回溯性约束**：LLM 只做候选关联与摘要，结论必须绑定证据 id，抑制幻觉。

## 六、评估设计（初稿）

- **任务集**：缺陷修复、功能新增、重构、测试补充、依赖升级五类，每类 2–4 个，共 10–20 个；在固定开源仓库上进行，保证可复现。
- **客观指标**：变更-对话关联的准确率/召回率（人工标注金标准）、溯源查询的正确率、任务恢复任务用时、问题定位用时。
- **主观指标**：理解正确率（受试者回答「这段代码为什么改」的评分）、NASA-TLX 认知负荷、SUS 可用性。
- **基线**：git log + diff + 原始聊天记录（即现有工具组合）。
- **受试者**：5–8 名有编程经验的同专业同学（小样本，结论表述为「初步证据」）。

## 七、风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| 真实智能体事件格式不统一/难采集 | 采集工作量失控 | 先支持一种（CLI 日志 + git），用适配器模式扩展；样例数据兜底 |
| 关联准确率低 | 溯源不可信 | 引入人工确认/修正入口；LLM 只做候选；评测中报告置信度 |
| 界面工作量过大 | 影响论文进度 | 先做 Web 最小可用版，砍掉非核心视图 |
| 用户实验招募困难 | 评估不充分 | 以客观指标为主，用户实验作为补充 |
| 时间不足 | 延期 | 按 WP 里程碑推进，中期前必须跑通「一次会话→变更→测试」闭环 |

## 八、与现有工具的差异（答辩常问）

- **Cursor / Claude Code / Cline**：有对话与 diff，但以会话/文件为单位，跨会话的任务上下文与「为什么改」的证据链弱。
- **git / local history**：记录文件快照，不记录触发原因与验证依据。
- **LangSmith / Langfuse 等 LLM 可观测性平台**：记录 trace 与 token，但不与代码变更、测试结果做语义级对齐，面向的是「调用链调试」而非「开发任务理解」。
- **本系统定位**：面向单个开发者的**任务级**开发过程记忆与溯源层，可与上述工具共存（作为其下游消费者）。
