### 致命一：创新点 1 与"研究空白"已被前作直接证伪

**位置**：第 89 行（研究述评）、第 234 行（创新点 1）

**原文**：
> "缺少以开发任务为中心、跨对话/代码/执行/测试四类异构记录的统一关联模型"

**事实**：Kersten 与 Murphy 在 FSE 2006 发表的 *Using task context to improve programmer productivity*（DOI 10.1145/1181775.1181777，被引 330+）正是"任务上下文 + 任务聚焦界面"的开创工作，Mylyn 即其产物。**"任务上下文（task context）"这个词就是从这条线来的**——你在第 43 行把它当作自己的核心概念界定，却没有引它的出处。

**最致命的一点**：这篇文献的证据不在别处，**就在你自己引用的 [20] 的正文引言里**。Parnin & Rugaber 2011 原文写道：

> "Kersten and Murphy (2006) have proposed a model that captures some aspects of task knowledge. Task context refers to the relevant artifacts of a program… Mylyn, a plugin available with Eclipse, allows users to filter code documents based on a selected task and recent activity."

也就是说：**线索就在你手上，你只读了 [20] 的正文，没有顺着它的参考文献往回追一步。** 答辩时评委只要说一句"Mylyn 2006 不是已经做了吗"，创新点 1 就当场失效。

**同类问题（同一段落的连带风险）**：
- 创新点 3"面向中断恢复的上下文重建"：Parnin & DeLine, CHI 2010, *Evaluating cues for resuming interrupted programming tasks*（DOI 10.1145/1753326.1753342）已用实验比较恢复线索类型；
- 研究内容（2）"任务边界判定"：Safer & Murphy, CASCON 2007, 标题就叫 *Comparing episodic and semantic interfaces for **task boundary identification***；
- 这三条**全部出现在 [20] 的正文或参考文献表里**（已从 PDF 文本流逐字核实）。

**改法**（可直接采用，完整版见 `docs/review/01` 第五节）：

### 致命二：溯源模型缺国际标准，第 73/89 行的断言在 2025 年后事实不成立

**位置**：第 71–73 行、第 89 行、第 51 行（五元关联模型定义）

**问题**：你以"provenance（溯源）"为核心概念，只引了 Cheney 等人的数据库溯源**理论**，却没有引：
- **W3C PROV-O**（2013）：溯源领域的国际标准本体，Entity / Activity / Agent 三元结构 + wasDerivedFrom / wasGeneratedBy / wasAssociatedWith 关系；
- **PROV-AGENT**（Souza et al., IEEE e-Science 2025, arXiv:2508.02866）：已把 PROV 扩展到 AI agent 交互（prompt / response / decision / MCP）。

**后果**：第 73 行"缺少对'指令—修改—验证'链路的建模"、第 89 行"明确的空白"，在 2025 年之后**事实不成立**。评委只要问一句"你为什么不用 PROV？"，你现在的稿子答不上来。

**这其实是加分项而非减分项**：五元模型完全可以表述为 PROV 在"智能体开发任务"场景下的**特化（profile）**，并给出一张 8 行的映射表（Task→Activity、Message→Entity、ToolCall→Activity、FileChange→Entity、TestRun→Activity、Agent=智能体/开发者……）。这样既回答了"为什么不用 PROV"，又让系统获得了**可导出、可互操作**的额外卖点。

### 致命四：实验设计无法支撑因果结论（这是最容易被评委按住打的地方）

**位置**：第 194–204 行、表 7-1

四个问题叠加，导致"系统有效"这一结论不可辩护：

**(1) 功效自相矛盾——明知不足而为之。**
第 200 行自己写："按配对设计 α=0.05、检验力 0.8、预期效应量 d=0.8 估算约需 15 人"，同句又写"受招募条件限制适当缩小样本"至 8–12 人。实测：n=10 时**最小可检出效应 d≈0.89**；若改用第 204 行承诺的 Wilcoxon 需约 17 对；若对 10 项指标做 Bonferroni 校正需约 21 对；若按工具类研究更现实的 d=0.5 估算需约 32 对。**工具类研究常见效应量在 0.4–0.6，真实效应大概率检不出。**

**(2) 归因链断裂——没有消融，且基线信息量不对等。**
系统含 LLM 摘要、证据链、恢复视图、任务组织四类组件，实验却只有"系统 vs Git+原始会话+测试报告"一个对比。更严重的是：系统侧有 LLM 生成的摘要与意图归纳（第 165 行），基线侧只有原始记录。**测出来的任何提升，都可能全部来自"摘要"这一文献中已知有效的干预，而非你主张的"关联与溯源"。** 评委必问："你的提升是来自任务组织，还是来自摘要？"

**(3) 主指标不可复现。**
表 7-1"关联准确率/召回率/F1"写"以变更块为单元"，但第 121 行自己承认"一次修改可能由多轮对话共同促成"——**多对多匹配规则完全未定义**：一个 hunk 对应 3 条消息时，返回其中 1 条算 TP 还是 FP？一条消息触发多个 hunk 怎么算？金标准是"必需集"还是"充分集"？无触发消息的 hunk 是否入分母？不定这些，F1 ≥ 0.75 既不可复现也不可与他人比较。**而且标注单位是"变更—消息候选对"（第 173 行），指标单位是"变更块"，两个单位不一致。**

**(4) 阈值列语义混杂。**
表 7-1"预期达标线"列里，183–185 行是硬阈值（F1≥0.75 等），186–188 行写"报告效应量""均值提升并报告区间"（不是阈值），189–190 行是相对/绝对阈值混用（"低于基线""≥70"）。同时第 103、177 行两处声明"不以达标线替代结论"——**既列硬阈值又不承认其结论地位，反而暴露作者自己也不确定**。

**改法（三选一，建议 B）**：
- A. 保留 8–12 人 → **全文改为 estimation study**，删"预期达标线"列与"需 15 人"的推算；
- **B. 推荐：定位降级为"探索性估计研究"**，只报效应量 + 95% CI（bootstrap BCa），不做确证性检验；补 2 个低成本消融（离线 leave-one-out + 受试者条件"去 LLM 摘要"）；补 B1 信息量对等基线；指标从 10 项压到 8 项；
- C. 要确证 → 样本提到 ≥21，或只保留 1 个主指标据此估算 n。

完整替代方案（含修订版表 7-1、实验设计改写、进度重排）见 `docs/review/02` 第四、五节。

### 致命五：技术可行性的地基只有一句断言，且与官方文档冲突

**位置**：第 214 行、第 145 行、第 218 行

**原文**：
> "主流代码智能体以结构化日志（如 JSONL）记录会话与工具调用……三类数据均可采集。"

**经官方文档逐页核实，这句话"部分成立但表述失准"**：

| 工具 | 事实 | 与报告表述的冲突 |
| --- | --- | --- |
| Claude Code | 官方**明确警告** `~/.claude/projects/*.jsonl` 为"内部格式、随版本变化、直接解析的脚本可能在任意版本失效"，推荐 hooks / `--output-format stream-json` / Agent SDK | 你把**易变实现细节当成了稳定契约** |
| Aider | 聊天记录是 `.aider.chat.history.md`（**Markdown**），不是 JSONL | "主流都是 JSONL"不成立 |
| OpenHands | 一事件一 JSON 文件（`events/event-00000-*.json`），不是单文件 JSONL | 同上 |
| Cursor | IDE 会话**无公开导出格式**；仅 CLI 有 NDJSON | 同上 |
| Cline | 本地 SQLite + 会话目录，**且 `providers.json` 里存着 API key** | 采集器整目录拷贝会带走凭据 |

更麻烦的是**保留期风险**：Claude Code 转录默认约 30 天清理、checkpoint 仅保留最近 100 个。若采集器等到实验结束才去读日志，**数据可能已经被清理**。

**同时，"零 spike"是硬伤**：第 145 行把"打通最小闭环"排在第三阶段（2026.12.01–12.20），等于**把最大风险放在最晚**。开题报告里没有任何一条实测证据、没有一段样例事件 JSON。评委不会问"SQLite 行不行"，会问"**你跑通过一次吗？日志里能拿到 old_string 吗？**"

**改法**：开题前两周内完成 3 个 spike（共 9–11 人日，清单与验收标准见 `docs/review/03` 第六节）：
1. **采集闭环（4 人日）**：Claude Code hooks + `stream-json` + git + 测试报告 → 统一事件表；验收：≥1 会话 / ≥30 事件 / ≥1 hunk / ≥1 test_run，消息→工具调用→文件变更连通率 100%，密钥扫描 0 命中；
2. **diff 对齐（3 人日）**：把 Edit 的 `old_string→new_string` 归一化为 hunk，与 git diff 比对；验收：hunk 级 IoU ≥ 0.90、定位成功率 ≥ 90%；
3. **多跳查询性能（2–3 人日）**：1 万事件库上测时间线/3 跳证据链/中文全文搜索；验收：热缓存 P95 ≤ 1 s。

**若 Spike 1 失败**，降级为"离线导入模式"，并同步下调评估规模——**这个降级路径必须写进表 8-1 风险表**。

## 七、可直接采用的替换文本（精选）

以下四段可直接粘贴替换，完整版见四份专项报告。

### 7.1 替换第 89 行"研究述评"（节选，完整版见 `01` 第 5.1 节）

> 需要说明的是，"以任务为单位组织开发上下文"并非全新命题。Mylyn 早在 2006 年就提出任务上下文（task context）模型，并以任务聚焦界面按当前任务过滤 IDE 中的代码元素；TaskTracer 在桌面层把文件、邮件与网页归集到任务；Codebook 建立了代码实体与提交、缺陷、邮件之间的关联图；SZZ 给出了"变更—问题"关联的经典算法。这些工作构成本课题的方法基础，但它们共享一个前提：开发者直接在 IDE 或桌面中操作，任务由人显式声明或由窗口切换间接体现。
>
> 当开发过程由代码智能体以自然语言指令驱动时，任务边界不再由用户显式激活，过程证据也从"编辑事件"变为"指令—工具调用—文件变更—测试运行"的异构序列；上述系统既没有面向智能体会话的事件模型，也没有把"验证依据"（测试）纳入证据链，更未处理跨会话的任务拼接与大模型生成摘要的可回溯约束。因此，本课题不主张"首次提出任务上下文"或"首次研究中断恢复"，而是在智能体辅助开发这一新场景下，给出可落地的任务上下文与变更溯源表示，并对有效性做可测量的评估。

### 7.2 替换第九章创新点 1（完整版见 `01` 第 5.2 节）

> **面向智能体会话的任务上下文重建。** 与 Mylyn 等以"用户显式激活任务 + IDE 代码元素"为前提的任务聚焦界面不同，本系统面向代码智能体产生的事件流：在任务边界不被显式声明的情况下，依据空闲时长、目标切换、显式指令与提交动作判定任务边界，把跨多次会话的对话、变更、工具调用与测试统一挂接到同一任务之下，形成可查询的任务上下文图。可验证差异：给定同一任务的两次会话记录，系统能自动归并为同一任务并返回完整上下文集合。

### 7.3 新增"（一）研究问题"（节选，完整版见 `02` 第 5.4 节）

> **RQ2（关联）**：在缺少显式标识的条件下，融合时间邻近、显式引用与代码位置映射的关联方法，其变更—消息关联的 P / R / F1 相对仅时间邻近基线提高多少？95% 置信区间为何？各关联信号的边际贡献如何（leave-one-out 消融）？
>
> **RQ4（续接）**：任务中断后，由进展摘要、未完成项与待验证修改构成的最小上下文，能否缩短恢复用时并提高理解要点命中数？该效果在移除大模型摘要后是否仍然存在（即效果来自组织方式还是摘要）？

### 7.4 替换第 214 行（数据可得性，完整版见 `03` 第三节结论 a）

> 主流代码智能体均提供机器可读的过程记录，但接口形态与稳定性差异显著：Claude Code 提供全生命周期 hooks 与 `--output-format stream-json`（其本地 `.jsonl` 转录为内部格式，官方声明随版本变化，故仅作降级通道）；OpenHands 将每个事件序列化为独立 JSON 文件；Cline 以会话为单位存于本地 SQLite 并用 shadow git 逐次记录快照；Cursor CLI 提供 NDJSON 事件流；Aider 仅提供 Markdown 对话记录与 git 提交。本课题据此采用"官方事件接口为主、日志直读为辅"的采集策略，为每个来源实现独立适配器并记录来源版本号，同时以 `fixtures/` 固化一份已验证的样例数据，保证格式变化时可回归。
