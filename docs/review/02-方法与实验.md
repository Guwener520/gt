## 一、总体判断

以当前设计执行，本课题只能得到「若干指标的一组观测值」，不足以支撑「本系统在代码理解、修改原因分析、问题定位、任务衔接四个维度上有效」这一结论；问题不在工作量，而在设计。第一，全文没有显式研究问题（检索「研究问题 / RQ / 假设」0 命中），五条研究目标、五块研究内容、四个关键问题、十项指标与七章论文结构之间不存在可检验的映射（见第三节），评估因此退化为指标罗列而非假设检验。第二，归因链断裂：实验只有一个对比「系统 vs Git + 原始聊天记录」（196 行），而系统含 LLM 摘要（100、115 行）与证据链、恢复视图、任务组织四类组件，既无消融、基线又与系统信息量不对等，测出的任何提升都可能全部来自「摘要」这一已知有效的干预。第三，统计框架与样本自相矛盾：200 行自认按 d = 0.8 需约 15 人却只招 8–12 人；若按 204 行改用 Wilcoxon 需约 17 对；若对 10 项指标作 Bonferroni 校正需约 21 对；n = 10 时最小可检出效应 d ≈ 0.89，而工具类研究常见效应量在 0.4–0.6，真实效应大概率检不出——属于「明知功效不足仍按确证性框架设计」。建议将定位整体降级为**探索性估计研究（exploratory estimation study）**：只报效应量与 95% CI、不做确证性检验，补 2 个成本可控的消融，补错误分析与伦理小节，把 10 项指标压到 8 项可执行指标，并把任务采集与标注从 3 周实验窗口前置到 2 月（第四节）。

## 四、最小可行评估方案（MVP-Eval）

约束：7 个月（2026.11–2027.05）、单人、8–12 名受试者、3 周受试者实验窗口、无额外经费。

### （一）定位与允许的结论

把研究定位写死为**探索性估计研究**，全文只允许以下三类结论：

1. 描述性事实：「在 12 个任务、约 X 个 hunk、Y 条候选对上，关联 F1 为 a（95% CI [b, c]）」；
2. 估计式比较：「完整系统相对基线的恢复用时中位差为 −m 分钟（95% CI [−p, −q]），效应量 d_z = …」；
3. 机制性观察：「移除 LLM 摘要后恢复用时变化为 …，说明提升主要／不完全来自摘要」。

**不允许**出现：「显著优于」「验证了系统有效」「达到达标线」「p < 0.05 表明」。这一定位直接消解 P2 的功效矛盾，也把评审的攻击面从「样本不足」转到「设计是否诚实」。

### （三）样本与统计

- **样本**：n = 10（8–12 区间内取 10；若只能招到 8，在局限中写明 n = 8 并给出所有 CI）。每名受试者完成 3 个任务 × 3 个条件（3×3 拉丁方平衡条件与任务顺序），单次到访 75–90 分钟。
- **条件**：B0 = Git + 原始会话 + 测试报告；C2 = 完整系统；C3 = 系统去 LLM 摘要。B1 = B0 + 自动摘要作为信息量对等条件，仅在离线对照与 2 人 pilot 中使用（若时间允许，把 B1 升为第 4 个受试者条件，但需 n ≥ 12）。
- **主指标 2 个**：任务恢复用时、理解要点命中数。其余为探索性，**不做多重比较校正**，因为不做确证性检验；在方法节明确写「探索性分析，未校正，p 值与 CI 仅供描述」。
- **统计**：报每条件中位数、配对中位差、bootstrap BCa 95% CI（10000 次重抽样）；效应量报 d_z 或 r（与检验匹配）；不报 p 值，或报但在括号注明「探索性，不作结论依据」。
- **缺失**：退出不补，报告完成率与退出原因；异常值不删除，在附录给出原始数据散点。

### （四）消融设计（两处，成本可控）

1. **离线消融（必做，0 受试者成本）**：在 400 条候选对标注数据上，对关联算法做 4 次 leave-one-out——去时间邻近、去显式引用、去位置映射、去 LLM 补全；每次报 P/R/F1 与相对完整算法的 ΔF1（bootstrap CI）。产物：表 7-3，一行一个消融条件。
2. **受试者消融（必做，只多 1 个条件）**：C2 vs C3（去 LLM 摘要）回答「提升是否来自摘要」；这是评审最可能追问的一点，必须在论文里有数字。

> **（一）研究问题**
>
> 本课题围绕「单个开发者使用代码智能体时，开发过程信息如何被组织、溯源与恢复」这一总问题，提出以下五个可检验的研究问题。
>
> **RQ1（表示）**：面向「任务—对话—变更—执行—测试」五类异构记录的统一事件模型，能否在不修改采集端的前提下覆盖至少两种来源（CLI 日志与 Git）的全部记录类型？以跨源事件覆盖率与位置映射成功率度量。
>
> **RQ2（关联）**：在缺少显式标识的条件下，融合时间邻近、显式引用与代码位置映射的关联方法，其变更—消息关联的 P / R / F1 相对仅时间邻近基线提高多少？95% 置信区间为何？各关联信号的边际贡献如何（leave-one-out 消融）？
>
> **RQ3（溯源）**：以变更块为粒度、绑定触发消息与验证测试的证据链，能否在 30 条预注册查询上达到可用的命中率？引入大模型补全后，命中率与结论不支持率如何权衡？
>
> **RQ4（续接）**：任务中断后，由进展摘要、未完成项与待验证修改构成的最小上下文，能否缩短恢复用时并提高理解要点命中数？该效果在移除大模型摘要后是否仍然存在（即效果来自组织方式还是摘要）？
>
> **RQ5（边界）**：基于空闲时长、显式指令与提交动作的任务边界判定规则，在真实开发过程数据上的 precision / recall 处于什么水平？规则阈值对结果有多敏感？
>
