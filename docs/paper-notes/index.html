四个核心问题，各由谁支撑Problem → evidence

写开题报告或论文引言时，每个问题的"研究缺口"都可以由下面两篇文献共同支撑，一篇给问题、一篇给方向。

① 信息分散对话、diff、工具调用、测试结果分属不同界面
08 MSR 综述 系统描述了源码、变更日志、缺陷库等数据源之间长期缺乏关联的现象；03 OpenHands 则给出了「用统一事件流承载一切动作与观察」的正面解法。
② 缺少任务视角工具以会话或文件为单位，而非以开发任务为单位
05 MetaGPT 用 SOP 把任务拆成有依赖关系的结构化产物，说明「任务分解」可以被显式建模；06 ChatDev 用 chat chain 把瀑布阶段切成原子子任务，提供了另一种任务粒度划分方式。
③ 溯源断裂代码为什么改成这样，无法从代码反查证据
07 noWorkflow 给出 why / where / when 三类溯源查询的完整数据模型；02 SWE-agent 的 ACI 设计则说明了「工具调用轨迹」本身可以被结构化记录到什么细度。
④ 上下文丢失多轮修改、并行任务、中断重启后难以恢复
09 中断恢复 提供了「恢复主要靠人工重读、工具支持不足」的实证依据；01 SWE-bench 的 task instance 设计则示范了「把一段工作界定为一个可独立恢复的单元」该怎么切。
写作提醒

不要把这 9 篇堆成"相关工作罗列"。更有效的写法是：每个核心问题下先引一篇指出缺口（08 / 09），再引一篇说明已有解法能走到哪一步（07 / 03），最后说明你的工作补的是哪一段。这个「缺口—已有解法—你的位置」的三段式，比按年份排列的综述更像研究。

使用约定Conventions

页码与数字

每页标注的页码是 PDF 物理页码（用 pdftotext 分页后逐页核对），不是论文印刷页码——两者在会议论文里可能相差 1–2 页。引文进入正式论文时，请以出版方版本的页码为准。

离线与打印

所有页面无任何外部依赖，断网可正常打开；浏览器「打印 → 存为 PDF」会隐藏导航与按钮，保留正文与图表，可直接当纸质笔记用。右上角 ◐ 按钮切换深色模式，设置会记住。

可信度分级

每页第 08 节「原文金句」都是逐字摘录并标注页码，可直接引用；正文讲解中的判断性表述（尤其第 06 节「我的判断」）是整理者的分析，引用时请自行核实，不要当作原文观点。
